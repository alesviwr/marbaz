# ربات بازی‌های گروهی تلگرام

ربات تلگرامی برای بازی سنگ‌کاغذقیچی، دوز و مار‌و‌پله با دوستان، همراه با مدیریت امتیاز و جدول برترین‌ها.

## نکته مهم درباره «سرور»

تلگرام کد ربات رو خودش اجرا نمی‌کنه — این یه تصور رایج اشتباهه. کد پایتونِ ربات باید یه جایی ۲۴ ساعته در حال اجرا باشه تا پیام‌های تلگرام رو دریافت و پردازش کنه. این ربات از روش **polling** استفاده می‌کنه، یعنی:
- نیازی به دامنه یا SSL نداری (بر خلاف webhook)
- فقط کافیه پروسه‌ی پایتون رو روی VPS‌ات به‌صورت دائمی (با systemd) اجرا کنی

## دیپلوی روی Railway

Railway هم دقیقاً همون قانون بالا رو داره: پروسه باید مدام در حال اجرا باشه (که Railway خودش این کار رو برات می‌کنه — با هر بار ری‌استارت یا کرش، خودکار بالا میاره). چون ربات با polling کار می‌کنه، نیازی به دامنه یا باز کردن پورتی نیست.

### مراحل

1. **پروژه رو به گیت‌هاب push کن** (یا مستقیم با Railway CLI آپلود کن — `railway up`).
2. تو [railway.app](https://railway.app) یه **New Project → Deploy from GitHub repo** بزن و ریپازیتوری رو انتخاب کن.
   - Railway خودش با دیدن `requirements.txt` و `Procfile` تشخیص می‌ده پایتونیه و از `python bot.py` به‌عنوان دستور اجرا استفاده می‌کنه.
3. تو تب **Variables** پروژه، متغیر محیطی زیر رو اضافه کن:
   - `BOT_TOKEN` = توکنی که از @BotFather گرفتی
4. **نکته‌ی مهم درباره‌ی دیتابیس:** فایل‌سیستم Railway به‌صورت پیش‌فرض *ephemeral* هست — یعنی با هر دیپلوی جدید، فایل `games.db` (و امتیازات ذخیره‌شده) از بین می‌ره. برای جلوگیری از این:
   - تو تب **Volumes**، یه Volume جدید بساز و مثلاً روی مسیر `/data` mount کن.
   - یه متغیر محیطی دیگه هم اضافه کن: `DB_PATH` = `/data/games.db`
   - کد از قبل برای خوندن این مسیر آماده‌ست (پیش‌فرضش `games.db` تو همون پوشه‌ی پروژه‌ست، اگه Volume نذاری هم کار می‌کنه ولی امتیازات با هر دیپلوی پاک می‌شن).
5. Deploy رو بزن. تو تب **Deployments → Logs** باید خط `ربات در حال اجراست...` رو ببینی.

بعد از این تنظیمات دیگه لازم نیست خودت سرور رو مدیریت کنی — Railway خودش uptime و ری‌استارت خودکار رو انجام می‌ده.

## نصب روی VPS (جایگزین)

```bash
# 1. آپلود پروژه به سرور (یا git clone)
cd telegram-games-bot

# 2. ساخت محیط مجازی
python3 -m venv venv
source venv/bin/activate

# 3. نصب وابستگی‌ها
pip install -r requirements.txt

# 4. ساخت فایل .env
cp .env.example .env
nano .env   # توکن ربات رو از @BotFather بگیر و اینجا بذار
```

## گرفتن توکن ربات

1. تو تلگرام به [@BotFather](https://t.me/BotFather) پیام بده
2. دستور `/newbot` رو بزن و اسم و یوزرنیم دلخواه رو انتخاب کن
3. توکنی که می‌ده رو کپی کن و تو فایل `.env` مقابل `BOT_TOKEN=` بذار

## اجرای دستی (برای تست)

```bash
source venv/bin/activate
python bot.py
```

## اجرای دائمی با systemd (پیشنهادی برای VPS)

1. فایل `games-bot.service` رو باز کن و مسیرها (`WorkingDirectory`, `ExecStart`) و `User` رو مطابق سرور خودت اصلاح کن.
2. کپی به سیستم:

```bash
sudo cp games-bot.service /etc/systemd/system/games-bot.service
sudo systemctl daemon-reload
sudo systemctl enable games-bot
sudo systemctl start games-bot
```

3. چک کردن وضعیت و لاگ‌ها:

```bash
sudo systemctl status games-bot
sudo journalctl -u games-bot -f
```

با این تنظیمات، اگه سرور ری‌استارت بشه یا ربات کرش کنه، خودکار دوباره بالا میاد.

## نحوه بازی (با لینک دعوت)

هر کدوم از دستورهای بازی رو بزنی (حتی تو چت خصوصی با خود ربات)، یه لینک دعوت به شکل
`https://t.me/<bot_username>?start=join_...` می‌گیری. همون لینک رو برای دوستت بفرست —
هر جا که بخوای: تو همین ربات، تو یه گروه، دایرکت خودتون، هر چت دیگه‌ای. وقتی دوستت روی
لینک بزنه، یه چت خصوصی با ربات براش باز می‌شه و خودکار به بازی ملحق می‌شه.

- `/rps` — سنگ‌کاغذقیچی. هر نفر تو چت خصوصی خودش انتخابشو می‌زنه؛ چون تو چت جدا هستن،
  انتخاب هرکس طبیعتاً از دیگری مخفیه.
- `/ttt` — دوز. تخته‌ی بازی تو چت خصوصی هر دو نفر هم‌زمان به‌روزرسانی می‌شه؛ فقط نوبت کسی
  که باید بازی کنه فعاله.
- `/sl` — مار و پله، تا ۴ نفر. بعد از ساختن بازی، لینک رو برای چند نفر بفرست تا بپیوندن،
  بعد خودت (سازنده‌ی بازی) دکمه‌ی «شروع بازی» رو بزن.
- `/score` — دیدن امتیازات خودت
- `/leaderboard` یا `/leaderboard ttt` یا `/leaderboard sl` — جدول برترین‌ها (برای همه قابل دیدنه)

> نکته: اگه خودت رو لینک بازی خودت باز کنی، ربات میگه «این لینک بازی خودته» — چون باید
> برای یه نفر دیگه بفرستیش، نه خودت باز کنی.

## دستور ادمین

- `/users` — فقط برای ادمین(های) ربات کار می‌کنه (کسانی که آیدی عددی‌شون تو متغیر
  `ADMIN_IDS` باشه). لیست همه‌ی کاربرایی که تا حالا با ربات کار کردن (اسم، یوزرنیم، آیدی
  عددی) رو نشون می‌ده — بقیه‌ی کاربرا اصلاً بهش دسترسی ندارن و حتی نمی‌دونن این دستور
  وجود داره.

### گرفتن آیدی عددی خودت برای ADMIN_IDS

تو تلگرام به [@userinfobot](https://t.me/userinfobot) پیام بده، آیدی عددیت رو بهت نشون
می‌ده. همون عدد رو تو `.env` مقابل `ADMIN_IDS=` بذار (برای چند ادمین، با کاما جدا کن:
`ADMIN_IDS=111111,222222`).

## ذخیره‌سازی امتیازات

امتیازها تو یه فایل SQLite به اسم `games.db` (کنار bot.py) ذخیره می‌شن و بین ری‌استارت‌های ربات از بین نمی‌رن. اگه خواستی از صفر شروع کنی، کافیه این فایل رو حذف کنی.

## ساختار پروژه

```
telegram-games-bot/
├── bot.py                  # نقطه‌ی ورود، ثبت دستورها + مسیریابی لینک‌های دعوت
├── config.py                # خواندن توکن و ADMIN_IDS از .env
├── database.py               # مدیریت SQLite (کاربرها و امتیازات)
├── game_sessions.py           # مدیریت مشترک بازی‌های چندنفره روی چت‌های خصوصی جدا
├── games/
│   ├── rps.py                # سنگ کاغذ قیچی
│   ├── tictactoe.py           # دوز
│   └── snakes_ladders.py       # مار و پله
├── requirements.txt
├── Procfile                   # دستور اجرا برای Railway
├── .env.example
└── games-bot.service          # نمونه سرویس systemd (برای VPS)
```
